# Speciai-kakao-bot 기능 명세서

작성일: 2026-08-13. 리뉴얼 전 현행(as-is) 기준.

## 1. 시스템 개요

거래처 카카오톡 단톡방을 개인 카톡과 분리해 수집·열람·발신하는 사내 콘솔.

| 구성요소 | 스택 | 역할 |
|---|---|---|
| 봇 단말 | 안드로이드 + 메신저봇R + `bot/speciai-bot.js` (Rhino ES5, 1,988줄) | 카톡 알림 파싱 → 서버 인입, 발신 큐 실행 |
| 웹 콘솔 | Next.js 15 App Router · React 19 · TS strict | 거래처별 대화 열람, 발신, 관리 |
| DB | Supabase (Postgres + Auth + Storage), RLS 워크스페이스 격리 | 저장·인증·권한 |

원칙:
- 필터는 서버에서 (`DEVICE_FILTER=false`). 미매칭 방은 본문 저장 안 함 — 방 이름·횟수만 기록
- fail-closed: 봇이 규칙 미수신 상태면 아무것도 전송 안 함
- AI 없음. 매칭·멱등·집계 전부 결정론
- 봇 자동응답 없음. 방에 쓰는 글은 대시보드에서 사람이 쓴 것뿐

## 2. 데이터 모델

| 테이블 | 역할 |
|---|---|
| `workspaces` | 워크스페이스. `staff_aliases` (우리 직원 이름 목록) 보유 |
| `memberships` | 소속 + 역할 (owner / admin / viewer) |
| `invitations` | 이메일 초대 |
| `partners` | 거래처 — 회사명만 |
| `partner_room_rules` | 방↔거래처 연결 규칙. kind: exact / prefix / contains / regex + priority |
| `kakao_rooms` | 카톡 방. room_key, room_name, pinned, handled, color |
| `kakao_messages` | 메시지. `(room_id, content_hash)` 유니크 |
| `kakao_unmatched_rooms` | 미분류 방 — 이름·수신 횟수만 |
| `kakao_outbound` | 발신 큐. pending → claimed → sent / failed |

식별·멱등 규칙:
- `room_key` = `chat:<chatId>` (API2) 또는 `name:<정규화 방이름>`
- `content_hash` = `log:<logId>` 또는 `md5(분단위시각|발화자|본문)`
- 발화자 판정: `staff_aliases` 매칭 시 `side='us'`, 아니면 `'partner'`. 부분일치는 3자 이상 별칭만

## 3. 봇 단말 기능 (`bot/speciai-bot.js`)

### 3.1 수집
- 트리거 2개 병행: 메신저봇R 메시지 콜백(API2 `Event.MESSAGE` / 구 `response`) + 알림 훅(`handleKakaoNoti`). 순서 비보장 → 단말 20초 중복 클레임 + 서버 멱등키로 이중 방어
- 방 제목 복원: 알림 `android.title`은 발신자명. 방 제목은 `conversationTitle → hiddenConversationTitle → subText → summaryText → infoText` 순으로 탐색. 전부 없으면 `방#<threadId>` 생성명 부여
- 1:1 방: 상대 이름 = 방 이름. 미등록 1:1은 전송 자체를 안 함
- 사진: 등록된 방만 단말에서 선필터 후 업로드 (`PHOTO_ONLY_FROM_KNOWN_ROOMS`)
- 규칙 동기화: 10분마다 `GET /api/kakao/bot/rules`. ingest 응답에 registered/unregistered 오면 즉시 재수신

### 3.2 방 등록 명령 (카톡방 안에서)
| 명령 | 동작 |
|---|---|
| `#등록 <회사명>` | 이 방을 해당 거래처에 연결 (`exact` 규칙 1건 생성). 거래처가 대시보드에 미리 있어야 함 |
| `#등록해제` | 수집 중지. 기존 대화는 보존 |

규칙 밖 방에서 서버로 나가는 메시지는 이 두 명령뿐. 서버는 명령을 저장하지 않고 규칙만 수정.

### 3.3 발신
- `POST /api/kakao/bot/outbox` 폴링으로 큐 클레임 → 전송 → ack
- 전송 폴백 4단: ① API2 `bot.send` ② 해당 방 마지막 replier ③ 알림 RemoteInput ④ `Api.replyRoom`
- 4초 이상 간격 + 무작위 지연 (카카오 자동화 탐지 회피)
- 규칙에 없는 방으로는 발신 안 함 (단말 재검사)

## 4. 서버 API

### 4.1 봇용 (`X-Ingest-Token` 인증)
| 엔드포인트 | 기능 |
|---|---|
| `POST /api/kakao/bot/ingest` | 메시지 인입. 매칭 먼저 → 매칭 방만 저장(사진 포함). 미매칭은 unmatched 카운트만. `#등록` 명령 처리. 응답에 해당 방 outbox 동봉 가능 |
| `GET /api/kakao/bot/rules` | 연결된 방 규칙 목록 `{ version, rules: [{kind, pattern}] }` |
| `POST /api/kakao/bot/outbox` | 발신 큐 클레임 + 직전 결과 ack |

### 4.2 콘솔용 (Supabase Auth 세션)
| 엔드포인트 | 기능 |
|---|---|
| `GET /api/kakao/rooms` | 방 목록 폴링(30초). 본문 미포함 |
| `GET /api/kakao/thread` | 방 대화 지연 로드 |
| `POST /api/kakao/room-state` | 고정 · 처리완료 · 색상 토글 |
| `POST /api/kakao/send` | 발신 큐 적재 (viewer 불가, role 판정). 상태는 항상 pending으로 반환 |
| `GET /api/kakao/partners` | 거래처 + 미분류 방 폴링 |
| `POST /api/kakao/room-delete` | 방 삭제 |

## 5. 서버 액션

| 모듈 | 기능 |
|---|---|
| `auth.ts` | 카카오 OAuth · 이메일 로그인/가입 · 비밀번호 재설정 · 로그아웃 |
| `members.ts` | 초대, 대기 계정 승인, 역할 변경, 멤버 제거, 초대 수락 |

| 뷰 | 기능 |

## 7. 매칭 규칙 엔진 (`src/server/kakao/rules.ts`)

- kind: `exact` · `prefix` · `contains` · `regex`
- 충돌 시 우선순위: priority → 긴(구체적인) 패턴 승
- 방 이름 정규화 후 비교. 생성명(`방#…`) 판별 함수 별도
- 동일 로직이 봇 스크립트 `matchRule`에 중복 구현 — 문법 변경 시 양쪽 동시 수정 필수

## 8. 비기능 요구사항·제약

- 개인정보: 미매칭 방 본문 미저장. 매칭 방은 원문 저장(마스킹 없음), 접근은 RLS. 방 참여자 사전 고지·동의 필요(개인정보보호법 §15)
- DB 공유: `linktalk` 앱과 같은 Supabase. `is_workspace_member()`는 `memberships` ∪ `workspace_members` 합집합(`0005`). `0001_base.sql` 운영 재실행 금지
- 봇 환경: Rhino ES5 (화살표 함수 · let/const · 템플릿 리터럴 금지)
- 브랜딩: `src/lib/brand.ts` + `NEXT_PUBLIC_BRAND_*` 환경변수로 일원화
- 필수 env: Supabase 3종 + `KAKAO_INGEST_TOKEN` (+ 선택 `KAKAO_WORKSPACE_ID`)
- 검증: `npm run typecheck && npm test && npm run build` (vitest: commands · outbound · rules · signup-policy)

# 거래처 카톡 봇 셋업 가이드

업무 전용 안드로이드 단말의 봇 계정을 거래처 단톡방에 초대해, 그 방 메시지만 대시보드로
자동 수집한다. 개인 카톡은 단말에서 차단되어 서버로 전송되지 않는다.

## 0. 전제 (법적 요건)

- **참여자 사전 동의 필수.** 각 거래처 단톡방 참여자에게 "메시지가 자동 수집·저장된다"는
  사실을 사전 고지·동의받아야 한다(개인정보보호법 §15). 동의 없는 방 수집 금지.
- 카카오 이용약관상 자동화 도구는 봇 계정 정지 리스크가 있다. 업무 전용 계정으로 운용할 것.
  이 봇은 카톡방에 **말하지 않고 읽기만** 하므로 리스크는 그만큼 낮다.

## 1. 구성

```
[업무 단말: 메신저봇R + bot/speciai-bot.js]
  ① GET  /api/kakao/bot/rules   (10분마다) → 방 이름 규칙 캐시
  ② 메시지 수신 → 규칙 매칭
       걸림   → POST /api/kakao/bot/ingest
       안 걸림 → 전송 안 함 (개인 카톡 보호)
        ↓ HTTPS
[웹 콘솔 (Vercel)]
  거래처 매칭 → kakao_rooms / kakao_messages 저장 → "받은 카톡" 탭에 표시
```

## 2. 서버 준비 (1회)

### 2-1. DB 마이그레이션

```bash
supabase db push        # 0001_base.sql → 0002_kakao.sql
```

### 2-2. 환경변수 (Vercel Production)

| 키 | 설명 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase 접속 |
| `SUPABASE_SERVICE_ROLE_KEY` | 봇 인입이 RLS 를 우회하는 데 필요 |
| `NEXT_PUBLIC_APP_URL` | 배포 도메인. 봇 연동 탭이 안내 주소를 만든다 |
| `KAKAO_INGEST_TOKEN` | 봇↔서버 공유 머신 토큰. `openssl rand -hex 32` |
| `KAKAO_WORKSPACE_ID` | 봇이 쌓을 워크스페이스 UUID |

`KAKAO_WORKSPACE_ID` 를 비워두면 워크스페이스가 정확히 하나일 때만 그것으로 폴백한다.
둘 이상이면 **인입이 503 으로 거부된다** — 엉뚱한 곳에 쌓는 것보다 안 받는 편이 낫기 때문이다.

### 2-3. 거래처 규칙 등록

콘솔 → **거래처** 탭 → 거래처 추가. 거래처명을 치면 접두어가 `[이름]` 으로 자동 제안된다.

> ⚠️ **규칙이 0개면 봇은 아무 방도 보내지 않는다.** 최소 1개는 등록해야 수집이 시작된다.

등록 전에 같은 탭의 **규칙 시험**에 실제 방 이름을 넣어 어느 거래처로 붙는지 확인할 것.
접두어에 대괄호를 빠뜨리거나 공백이 어긋나면 조용히 아무것도 안 걸린다.

## 3. 단말 세팅

1. Play스토어에서 **메신저봇R** 설치
2. 권한 허용: **알림 접근**(수신), **배터리 최적화 해제**(상시 실행)
3. 봇 새로 만들기 → `bot/speciai-bot.js` 내용 전체 붙여넣기 (기존 코드는 지운다)
4. 스크립트 상단 설정 3줄 채우기 — 값은 콘솔 **봇 연동** 탭에서 복사 버튼으로 가져올 수 있다:
   - `ENDPOINT` = `https://<배포도메인>/api/kakao/bot/ingest`
   - `RULES_ENDPOINT` = `https://<배포도메인>/api/kakao/bot/rules`
   - `TOKEN` = 서버 `KAKAO_INGEST_TOKEN` 과 같은 값
5. **컴파일 ON**
6. 봇 계정(단말에 로그인한 카톡)으로 각 거래처 방에 초대

## 4. 스모크 테스트

### 4-1. 규칙 배포 확인 (curl)

```bash
curl -s https://<배포도메인>/api/kakao/bot/rules \
  -H "X-Ingest-Token: $KAKAO_INGEST_TOKEN"
# 기대: {"version":"...","rules":[{"kind":"prefix","pattern":"[삼성전자]"}]}
```

`rules` 가 빈 배열이면 거래처 탭에서 규칙부터 등록한다.

### 4-2. 서버 인입 확인 (curl)

```bash
curl -s -X POST https://<배포도메인>/api/kakao/bot/ingest \
  -H "Content-Type: application/json" \
  -H "X-Ingest-Token: $KAKAO_INGEST_TOKEN" \
  -d '{"room":"[삼성전자] 3분기 발주","sender":"박부장","text":"납기 확인 부탁드립니다"}'
# 기대: {"ok":true,"inserted":1,"skipped":0}
```

규칙 밖 방으로 보내면 `{"ok":true,"inserted":0,"skipped":0,"unmatched":true}` 가 온다
(저장 안 됨). 같은 요청을 1분 안에 다시 보내면 `inserted:0, skipped:1` — 멱등 동작 확인.

### 4-3. 단말 실연동

1. 봇이 들어간 거래처 방에 메시지 전송 → 콘솔 "받은 카톡" 탭에 뜨는지 확인
2. 규칙 밖 방(개인 카톡)에 메시지 전송 → **콘솔에 아무것도 안 뜨는지** 확인
3. 메신저봇R 로그에 `규칙 밖 방 스킵 room="..."` 이 찍히면 정상 (본문은 로그에도 안 남는다)

## 5. 동작 규칙 요약

| 상황 | 동작 |
|---|---|
| 방 이름이 규칙에 걸림 | 단말 → 서버 전송 → 거래처 매칭 후 저장 |
| 방 이름이 규칙에 안 걸림 | **단말에서 차단.** 서버로 전송 자체를 안 함 |
| 봇이 규칙을 한 번도 못 받음 | 아무것도 안 보냄 (fail-closed) |
| 서버가 `unmatched` 응답 | 봇이 즉시 규칙을 재조회해 다음부터 안 보냄 |
| 동일 메시지 중복 수신 | `content_hash` 로 skip |
| 새 메시지 도착 | 그 방의 "처리완료" 표시가 자동 해제됨 |

## 6. 문제 해결

| 증상 | 원인 · 조치 |
|---|---|
| 아무것도 안 들어옴 | 거래처 규칙 0개. 거래처 탭에서 등록 |
| 특정 방만 안 들어옴 | 방 이름과 접두어 불일치. **규칙 시험**으로 확인. 공백·대괄호 확인 |
| 방 이름 대신 사람 이름으로 뜸 | 단말이 방 제목을 못 읽는 상태. **카톡에서 방 제목을 지정**하면 해결 |
| `#등록` 을 쳐도 아무 일도 안 남 | 로그의 `kakao-bot[NOTI] room="..."` 를 본다. 방 제목 자리에 사람 이름이 있으면 서버가 등록을 거부한 것이다(그 이름으로 규칙을 만들면 그 사람이 말하는 **모든 방**이 이 거래처로 붙는다). 카톡에서 방 제목을 지정할 것 |
| 로그에 `단톡방인데 방 제목이 발신자명과 같다` | 위와 같음. 방 제목 미지정 단톡방이다 |
| 대시보드에서 보낸 것이 `failed` | 그 방 알림 세션이 만료됐다. 거래처가 그 방에서 한 번 말하면 통로가 되살아난다. 등록된 방에서 `#전송테스트` 를 치면 네 경로 중 어느 것이 되는지 로그에 찍힌다 |
| 로그에 `규칙 미수신` | 단말이 서버에 못 닿음. `RULES_ENDPOINT`·`TOKEN` 확인 |
| 인입이 503 | `KAKAO_WORKSPACE_ID` 미설정 + 워크스페이스 2개 이상 |
| 사진이 안 뜸 | 단말·메신저봇R 버전에 따라 base64 추출 경로가 없을 수 있다. 텍스트는 정상 수집 |

## 7. 한계

- 단말 화면 꺼짐·앱 종료·재부팅 시 수집 중단. 배터리 최적화 해제·상시 충전 권장.
- 규칙을 나중에 등록해도 **미분류 구간의 지난 대화는 복구되지 않는다.** 그 구간에는 본문을
  저장하지 않았기 때문이다(개인 대화 보호를 위한 설계). 등록 이후 메시지부터 쌓인다.
- 콘솔에서 보낸 글은 **즉시 나가지 않는다.** 큐에 쌓였다가 봇이 가져가 방에 넣는다
  (`pending` → `sent`). 그 방의 알림 세션이 만료됐으면 `failed` 로 뜨고, 거래처가 그 방에서
  한 번 말하면 통로가 되살아난다.
